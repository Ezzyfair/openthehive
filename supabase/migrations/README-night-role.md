# ezzy_night — the night-shift read-only role (NIGHT-ROLE-001)
- **The role.** `ezzy_night` is Ezzy's night-shift database login: LOGIN, NOINHERIT, not superuser, no create, `statement_timeout` 30s, SELECT only. It had blanket `SELECT` on `public.*` but no RLS policy on any of the 39 tables, so every query returned 0 rows; v2 narrows the grants first, then opens what remains.
- **Already run.** `20261004_ezzy_night_read_v2.sql` was **RUN on Oct 4 2026 by Francis in the Supabase SQL editor**, after Nikita's PASS, and its verification query returned **27 | 0 | 53 | 0** — 27 `ezzy_night_read` policies, 0 excluded tables still granted, 53 `agents` columns granted, 0 secret `agents` columns granted. This commit only files what was run; nothing here re-runs it.
- **Carve-outs (Nikita's ruling on v1).** 12 token/member/money/backup tables are revoked outright — `bee_tokens`, `join_tokens`, `members`, `email_sends`, `email_suppressions`, `stripe_events`, `stripe_webhook_failures`, `payments`, `hive_revenue`, `referral_earnings`, `referral_transactions`, `honeycombs_bak_20260925` — and 11 secret or PII columns on `agents` are revoked: `agent_api_key`, `eth_wallet`, `stripe_customer_id`, `strike_username`, `email`, `agent_email`, `human_name`, `human_bio`, `human_channel`, `notification_channel`, `config_file_url`. The remaining 27 tables each get one SELECT-only `ezzy_night_read` policy, and `ALTER DEFAULT PRIVILEGES` stops a future table being readable without an explicit grant.
- **Name explicit columns on `agents` — never `SELECT *`.** `agents` is a **column-level** grant, so `SELECT *` on it is refused for this role. Every night-shift query against `agents` must list the columns it wants. That is the design, not a fault to work around, and it is why the 53-column count is part of the verification.
- **Rollback.** `20261004_ezzy_night_read_v2_rollback.sql` drops every `ezzy_night_read` policy and returns the role to reading zero rows. It deliberately leaves the narrowed grants and the default-privilege revoke in place: less access is never a regression, and Nikita ruled the role/grant undo out of scope.
